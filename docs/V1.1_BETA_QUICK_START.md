# ForgeCare v1.1 Beta Quick Start

ForgeCare `v1.1.0-beta.1` is an unsigned, controlled beta for Windows 11 x64. Use it first on a non-critical test machine under a normal user account. ForgeCare does not silently elevate, automatically upload data, or execute system changes from diagnostic Evidence or Attention.

## Choose a build

- **Installer:** per-user installation under LocalAppData. A newer installer using the stable ForgeCare AppId upgrades the existing installation in place.
- **Portable:** extract the complete ZIP to a user-writable folder and run `ForgeCare.exe`. It still stores operational/session data under LocalAppData.

Both builds are self-contained and should not require Visual Studio or a separately installed .NET runtime.

## Before launch

ForgeCare beta artifacts are unsigned, so Windows SmartScreen may warn. Obtain artifacts only from the approved ForgeCare test source and compare the filename and SHA-256 hash with the supplied release manifest. Do not disable Windows security features globally.

## Recommended technician flow

1. Launch ForgeCare and open **Tools**.
2. Run **External Machine Preflight**.
3. Start a fresh Forge Report session, or restore the supported current session.
4. Run **System Scan**, then **Deep Analysis**.
5. Inspect persisted observations in **Evidence**.
6. Build **Forge Plan** and review read-only Attention separately from Plan Actions.
7. Optionally open an established action review workflow. Use Dry Run where supported and confirm every mutation explicitly.
8. After an eligible Startup action, run a later explicit System Scan to collect factual verification.
9. Generate the **Professional Report** for technician/customer handoff.
10. Run **Regression Suite**.
11. If support is needed, export a **Debug Bundle** and review its contents before sharing.

Core diagnostics and intelligence are local-first and use offline/cache-only trust inspection. Access-denied or unavailable observations can produce partial results; they are not treated as zero findings.

## Safety and verification

- Evidence and Attention are observational and read-only.
- System-changing actions remain behind existing review and confirmation paths.
- Startup undo/recovery is available only for supported Startup operations.
- Verification records what a later observation found. It does not prove performance improvement or causality.
- Not every service session requires a mutation. The current beta does not yet provide a persisted “review complete—no action required” workflow decision; document that outcome in technician handoff notes without fabricating an action or verification result.

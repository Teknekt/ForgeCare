# ForgeCare v1.1 Beta Known Limitations

This document describes intentional boundaries of `v1.1.0-beta.1`.

- Initial accepted beta target is Windows 11 x64. Windows 10 is not supported until artifact-tested; ARM64 has no native build.
- Beta artifacts are unsigned. Windows SmartScreen may warn.
- Typed Verification 2.0 currently covers supported Startup actions. Cleanup and Storage do not have equivalent typed action-linked verification.
- Startup Intelligence uses the existing limited startup-source families. Shortcut payload resolution and launcher payload interpretation remain deferred.
- ForgeCare provides diagnostic/provenance context, not a malware verdict, necessity verdict, or automatic optimization decision.
- No continuous monitoring, cloud intelligence, telemetry, or automatic remediation is provided.
- Authenticode evaluation is local/offline and does not prove fresh online revocation status or application safety.
- Evidence observations are append-only within a session and are not deduplicated by correlation key.
- Professional Reports export deterministic HTML; native PDF generation is not included.
- Access-denied, protected, exiting, or otherwise unavailable resources can produce incomplete/partial observations.
- Older ForgeCare builds may not understand newer schema-1 enum strings even though the Evidence document shape remains schema version 1.
- ForgeCare does not quantify performance causality. Successful execution and later observed outcome are distinct facts.
- A persisted “review complete—no action required” workflow decision is not yet implemented.
- Debug Bundles may contain sensitive local support, Evidence, settings, report, or recovery information and must be reviewed before sharing.
